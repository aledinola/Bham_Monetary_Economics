## Running the material

- **Lecture 2, Walrasian auctioneer:** run `matlab_codes/walrasian_auctioneer.m` in full. It is a standalone base-MATLAB script with no external data or helpers; it clears the workspace and closes figures. At the supplied settings, it performs exactly 50 wage updates, using relative excess demand `(labour demand - labour supply)/(labour demand + labour supply)` and adjustment speed `lambda = 0.1`. Its opening comments and the lecture supplement describe a tolerance-based stopping rule, but the current code does not implement that check. Inspect the residual and planner comparison rather than treating the iteration cap as a convergence guarantee.
- **Lecture 3, permanent income:** run `matlab_codes/lecture3_main.m` in full. It clears the workspace and closes figures, then displays the Ann-Bob comparison in a table and one figure. Negative `a` means borrowing; consumption equality is subject to numerical solver tolerance. No external helpers or data are needed.
- **Lecture 3:** open `matlab_codes/lecture3_extra.m` in MATLAB's Live Editor and run the whole file once before experimenting with individual sections. Both Huggett helpers are in that same folder; make `matlab_codes` the current folder or add it to the MATLAB path.
- **Lecture 3, precautionary saving:** open `matlab_codes/lecture3_precautionary_saving.m` in the Live Editor and run sections in order. Keep `hh_objective_precautionary.m` in that same folder and make it the current folder or add it to the MATLAB path.
- **Lecture 4:** open `matlab_codes/lecture4_investment.m` in the Live Editor and run sections in order. All calculations are contained in this file; no external helper or data files are required.
- **Seminar Class 1:** open `matlab_codes/seminar_class_1_matlab.m` in the Live Editor and run its sections in order. It has no external code or data dependencies. Its embedded `seminar_class_1.pdf` link assumes its former location and does not resolve from the central folder; the PDF remains in Dropbox at `2_seminar_classes/class_1/` and is not published in this repository. The script itself is unchanged.
- **Live-script format:** these `.m` files contain `%[text]` markup for MATLAB's Live Editor.
- **Seminar Class 3, wartime fiscal data:** run `2_seminar_classes/class_3/data_exercise/fiscal_wars_fred.m` in full. Paths are resolved relative to the script, so another starting working directory is supported. Data validation rejects missing plotting observations rather than interpolating. Real indices are checked numerically at their base dates. Government purchases exclude transfers and debt interest; chained-dollar components are not additive. Source notes and the accompanying local slides distinguish observed consumption from counterfactual crowding out.
- **Prescott calculation:** run `prescott` or `main_prescott` from `matlab_codes`. Each defines its own local `solve_country` helper. Both clear the workspace and close figures.
- **Davila calculation:** run `main_davila` from `matlab_codes`. All its functions are defined inside the file. It clears the workspace and closes figures.
- **Figure generator (Dropbox only):** use `app1.m` section by section in a separate output folder. It clears variables, closes figures and writes PNG/EPS files with fixed names. Some sections reuse output names, notably `lec10_4`, so a full run overwrites earlier versions. No external input files are loaded.

### Lecture 3 saving notation, 11 October 2026

The Huggett live script and both helpers now use `a` for saving today, matching the lecture slides: `c1 = y1 - a` and `c2 = y2 + R*a`. The household search interval is `-min(y2)/R < a < y1`, with a `1e-8` inward margin at each endpoint. Function signatures are unchanged, but the returned `a` now measures saving today rather than future payoff. The equilibrium solver retains its `[0.2,3]` bracket, 100-iteration cap, and `abs(a) < 1e-10` stopping rule, now measured in saving today.

MATLAB R2026a Code Analyzer reported no findings in the three edited files, and the complete live script ran successfully. Regression checks covered six parameter cases (the baseline, log utility, certain future income, and all three AI scenarios), each at 102 interest rates including both bisection endpoints. Consumption remained positive, budgets and Euler equations held, and both borrowing and saving occurred in each case. Compared with the previous formulation, saving equalled the old future payoff divided by `R`, and consumption was unchanged, with maximum absolute differences below `5e-16`. The largest scaled Euler residual was below `7e-16`. Every tested equilibrium met the saving tolerance and agreed with its closed-form rate within `1e-8`; the baseline gave `R = 0.923076923005`, `a = -1.906e-11`, and a rate difference of `7.164e-11`.

### Lecture 3 explicit scalar states, 17 October 2026

The Huggett live script and both helpers now describe the two income states using separate scalars. The parameter fields are `y2_L`, `y2_H` and `prob_L`; the high-state probability is `1-prob_L`. The household interface is `[a, c1, c2_L, c2_H] = huggett_household(R, par)` and the equilibrium interface is `[R, a, c1, c2_L, c2_H] = huggett_equilibrium(par)`. These replace the earlier vector income/probability fields and vector future-consumption output. All current callers and the analytical equilibrium formula use the scalar fields. Parameters are still unpacked into local variables in the household helper, and the live script retains the local `nR = 100` column-vector interest-rate grid. Solver algorithms, tolerances, preference parameters and calibrations are unchanged.
